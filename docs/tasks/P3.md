# P3 — OpenAI-compatible provider config + MCP server

Goal: any OpenAI-compatible endpoint works through `base_url` + `api_key` + `model` (Ollama, LM Studio, OpenRouter,
Qwen, DeepSeek, OpenAI), with an optional native Anthropic client. Any MCP client can drive the browser through BABAS
with the tools `run_task`, `get_page_state` and `act`, behind the same safety gate.

Read first: `docs/SAFETY.md` (no MCP path may skip a confirmation). P2 must be complete.

New dependencies, as optional extras only:
- `mcp = ["mcp>=2.3,<3"]`
- `anthropic = ["anthropic>=0.40"]`
- add `"mcp>=2.3,<3"` to `dev`

**MCP SDK 2.x is not the 1.x you may remember.** Verified on 2026-10-11 with mcp 2.3.0:
- `from mcp.server.mcpserver import MCPServer, Context` (`mcp.server.fastmcp` no longer exists);
- `server = MCPServer(name=..., instructions=..., version=...)` and `@server.tool(description=...)` on async functions;
  Pydantic parameters, including discriminated unions, become the input schema, and invalid arguments come back as an error result;
- `await ctx.report_progress(progress, total, message)`;
- `await server.run_stdio_async()` and `await server.run_streamable_http_async(host=..., port=..., streamable_http_path="/mcp")`;
- tests use `from mcp import Client` with `async with Client(server) as client:` (in memory);
  `(await client.list_tools()).tools[i].input_schema`; `res = await client.call_tool(name, args)` with
  `res.is_error`, `res.content[0].text` and `res.structured_content`. Fields are snake_case.

## Steps

### [x] P3.1 Settings (`babas/config.py`)
A frozen dataclass `Settings` with `@classmethod from_env(env: Mapping[str, str] | None = None)`. It calls
`load_dotenv()` only when `env is None`, and uses no extra dependency.
| field | env var | default |
|---|---|---|
| `llm_provider` | `BABAS_LLM_PROVIDER` | `"openai"` (`openai` = any OpenAI-compatible endpoint, or `anthropic`) |
| `llm_base_url` | `BABAS_LLM_BASE_URL` | `None` (OpenAI's default) |
| `llm_api_key` | `BABAS_LLM_API_KEY`, else `OPENAI_API_KEY` (openai) / `ANTHROPIC_API_KEY` (anthropic) | `None` |
| `llm_model` | `BABAS_LLM_MODEL` | `"gpt-5.2"` for openai; required for anthropic |
| `llm_json_mode` | `BABAS_LLM_JSON_MODE` | `"auto"` (`auto`, `json_schema`, `json_object` or `none`) |
| `llm_timeout` | `BABAS_LLM_TIMEOUT` | `60.0` |
| `allowed_domains` | `BABAS_ALLOWED_DOMAINS` | the defaults (comma list, or `*`) |
| `max_steps` / `max_retries` | `BABAS_MAX_STEPS` / `BABAS_MAX_RETRIES` | `30` / `2` |
| `language` | `BABAS_LANG` | `"es"` |
| `bridge_host` / `bridge_port` | `BABAS_BRIDGE_HOST` / `BABAS_BRIDGE_PORT` | `"127.0.0.1"` / `8765` |
| `extension_origins` | `BABAS_EXTENSION_ORIGINS` | the pinned origin |
| `home` | `BABAS_HOME` | `~/.babas` (`pairing.json` lives here) |
| `mcp_http_port` | `BABAS_MCP_HTTP_PORT` | `8766` |
| `log_level` | `BABAS_LOG_LEVEL` | `"INFO"` |

Invalid values raise `ValueError` naming the variable. Every entry point (`cli`, `serve`, `mcp`) builds one
`Settings` and passes it down; remove the direct `os.getenv` reads elsewhere. The P2 "missing key" message now fires
only when a key is really needed: `llm_provider == "anthropic"`, or `openai` with no `llm_base_url` (OpenAI cloud).
Local endpoints such as Ollama work without a key. `build_system_prompt(settings.language)`
adds "Write every explanation and the final answer in Spanish (Mexico)" for `es`.
Tests: `tests/test_config.py` covers the defaults, comma lists, `*`, the int and float parsing errors, and the `OPENAI_API_KEY` fallback.

### [x] P3.2 Providers (`babas/llm.py`)
`OpenAICompatibleClient(*, base_url, api_key, model, json_mode="auto", timeout=60.0)`:
- Builds `AsyncOpenAI(base_url=base_url, api_key=api_key or "not-needed", timeout=timeout, max_retries=2)`.
- Messages: `[{"role":"system","content":system},{"role":"user","content":user}]`.
- Modes:
  - `json_schema`: `response_format={"type":"json_schema","json_schema":{"name":"babas_plan","schema":schema,"strict":False}}`;
  - `json_object`: `{"type":"json_object"}`;
  - `none`: no `response_format`.
- `auto` tries `json_schema` (only if a schema is given), then `json_object`, then `none`. It moves to the next mode only
  on `openai.BadRequestError` or `openai.UnprocessableEntityError`, and caches the first mode that works on the instance.
  Any other `openai` error raises `LLMError` with a short message (never include the API key).
- Parses with `extract_json`. Empty content raises `LLMError`.
- `OpenAIClient` (from P2) becomes a thin subclass that reads the old env vars, so existing code keeps working.

`AnthropicClient(*, api_key, model, base_url=None, timeout=60.0)`:
- `import anthropic` happens inside `__init__`. If the import fails, raise
  `LLMError("Install the Anthropic extra: pip install 'babas[anthropic]'")`.
- Calls `await client.messages.create(model=model, max_tokens=4096, system=system, messages=[{"role":"user","content":user}])`,
  joins the text blocks, then `extract_json`.
- Do not hardcode a model id. If the `claude-api` skill is available in your session, check it for current SDK usage.

`make_llm(settings) -> LLMClient` picks the class from `llm_provider`.

`tests/fake_openai_server.py`:
- a `ThreadingHTTPServer` on `127.0.0.1:0` that answers `POST /v1/chat/completions`;
- it returns queued contents as a standard `chat.completion` JSON (`choices[0].message.content`);
- it replies 400 with `{"error":{"message":"response_format <type> is not supported","type":"invalid_request_error"}}`
  for any `response_format.type` in `reject_types`;
- it records request bodies and headers.

`tests/test_llm.py`:
- auto falls back json_schema → json_object → none, and the cached mode is used on the next call;
- fenced JSON is extracted and invalid JSON raises `LLMError`;
- the `Authorization: Bearer <key>` header and the `base_url` are used;
- `make_llm` picks the provider;
- the missing-package message for anthropic (monkeypatch the import to fail).

### [x] P3.4 MCP server (`babas/mcp_server.py`, `babas/__main__.py`)
```python
class McpRuntime:
    def __init__(self, settings: Settings, driver_factory: Callable[[], SafeDriver], llm: LLMClient, channel: UserChannel): ...
    lock: asyncio.Lock              # one browser-touching tool call at a time
    last_state: Optional[PageState]

def build_mcp_server(runtime: McpRuntime) -> MCPServer: ...
```
Server instructions (English): "BABAS controls the user's real Chrome through the BABAS extension. Consequential
steps (sending, submitting, paying, typing personal data) must be approved by the user in the BABAS side panel. You
cannot skip that. Logins and CAPTCHAs are always done by the user."

Tools:
Every tool that needs the browser calls `driver = runtime.driver_factory(); await driver.start()` inside the lock.
- `run_task(task: str, ctx: Context) -> dict`: runs `Agent` under `lock` with `on_event` →
  `ctx.report_progress(steps, settings.max_steps, message)`. Returns `{"status", "answer", "steps"}`.
- `get_page_state() -> dict`: stores `runtime.last_state`. Returns `state.model_dump()` with elements capped at 150,
  plus `"prompt": state.to_prompt()`.
- `act(action: ActStep) -> dict`: runs one action with `ActionExecutor` under `lock`. Index targets use
  `runtime.last_state.snapshot_id`; if no state was taken yet, take one first. Returns
  `{"ok": True, "detail", "url", "title"}`. Errors raise an exception whose message the client sees:
  - `ActionDenied` → "The user declined this action in BABAS.";
  - `HandoffRequired` → "Hand-off needed: <message>";
  - `DriverError` → "<code>: <message>".

Entry points:
- `python -m babas mcp` (stdio):
  1. Load settings and call `setup_logging`. If `import mcp` fails, print to stderr
     `Install the MCP extra: pip install 'babas[mcp]'` and exit 1.
  2. Start `BridgeServer(settings.bridge_host, settings.bridge_port, list(settings.extension_origins), pairing_file=settings.home / "pairing.json")`.
     If the port is busy (`OSError`), print to stderr "Port 8765 is in use (is `babas serve` running?). Stop it or use
     its HTTP endpoint: python -m babas serve --mcp-http" and exit 1.
  3. Build the runtime with `driver_factory=lambda: SafeDriver(ExtensionDriver(bridge), SafetyPolicy(settings.allowed_domains), PanelChannel(bridge))`
     and `channel=PanelChannel(bridge)`.
  4. `await server.run_stdio_async()`.
- `python -m babas serve --mcp-http`: the same runtime, sharing the serve bridge, plus
  `server.run_streamable_http_async(host="127.0.0.1", port=settings.mcp_http_port, streamable_http_path="/mcp")`,
  run with `asyncio.gather` next to the Session.

`tests/test_mcp.py`, an in-memory `Client(server)` whose runtime uses `SafeDriver(FakeDriver)`, a `RecordingChannel`
(which can approve after 0.2 s or deny) and `FakeLLM`:
- the tools are exactly `run_task`, `get_page_state` and `act`;
- the `act` schema contains the `action` discriminator;
- `get_page_state` returns the elements;
- `act` typing into a PII field waits for the approval, then succeeds with the confirmation id;
- a denial gives `is_error` with "declined";
- `run_task` returns `status == "done"`;
- invalid `act` arguments give `is_error`.

## As built (deviations from the steps above; all deliberate)
- **Settings.** `llm_api_key` is excluded from `repr`. `allowed_domains` EXTENDS the defaults (`*` means all), like
  `SafetyPolicy.from_env`; `extension_origins` entries must look like `chrome-extension://<32 letters>`; invalid
  values exit 2 naming the variable. `Settings.needs_api_key` drives every missing-key message.
  `SafetyPolicy.from_env` and `default_pairing_file()` still exist (P2 tests use them) but no entry point calls them.
- **Providers.** `make_llm` never raises for a missing key, model or package: the client raises `LLMConfigError` (a
  subclass of `LLMError`) on its first call naming the variable, so servers start and report per task. Auto mode falls
  back only on HTTP 400/422; `extract_json` also drops a leading `<think>…</think>` block; an answer cut off by the output
  limit and a refusal give their own messages. `OpenAIClient` stays as a thin compatibility subclass.
- **MCP.** Exactly three tools through `SafeDriver`; no tool has a "confirmed" flag. `act` with an element index
  requires a prior `get_page_state` (a silent re-snapshot would remap the client's old indices). `get_page_state` masks
  element values and drops password values. `run_task` masks its answer and is cancelled by Stop in the panel. `act`
  `screenshot` writes to `$BABAS_HOME/screenshots` (the working directory belongs to the MCP client). Every tool call
  builds a fresh driver. The SDK's root log handler is removed after building the server (it duplicated every log line).
- **HTTP transport.** `serve_http` builds the SDK's streamable-HTTP app with DNS-rebinding protection and runs its own
  uvicorn server (no signal takeover, no access log on stdout, bounded shutdown). It refuses non-loopback hosts and
  answers 421 to a foreign `Host` and 403 to a foreign `Origin`.
- **Wiring.** One `Settings.from_env()` per command; a `ValueError` prints `Invalid configuration: …` and exits 2. The
  missing `mcp` extra prints the install hint to stderr and exits 1. `serve --mcp-http` cannot be combined with `--repl`.
  `Session` gained `max_retries` and an optional `busy` hook (a panel task is refused while an MCP call holds the
  browser, and the MCP runtime refuses while the panel runs), closes the per-run LLM client, and shows one Spanish
  message for any `LLMConfigError`. `cli.main` now calls `setup_logging`.
- **Print audit (P3.3).** Prints remain only where they are the user interface: `cli.py`, `devrepl.py`, the `__main__`
  console commands, `ConsoleChannel`, and the CLI-only browser startup code in `debug.py` and `playwright_driver.py`.
  Nothing on the `mcp` or `serve --mcp-http` path writes to stdout (a real stdio run was checked). Values printed by
  `cli.py`/`devrepl.py` go through `redact`.
- **Not covered / manual:** real OpenAI-compatible providers and the real `anthropic` package (a fake module is used), real
  MCP clients (Claude Code/Desktop/Cursor), two MCP clients at once over HTTP (they share `last_state`), Windows,
  Python 3.10 for the new modules.
