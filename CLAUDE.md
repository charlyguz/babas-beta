# CLAUDE.md

BABAS (Browser Automation Bot Assistant System) is an LLM browser agent in Python. The user types or speaks a task,
and the LLM returns a JSON plan of Pydantic-validated actions that run in Chromium. When a step fails, BABAS re-plans
from the page context.

**Who it's for:** people with low digital literacy, first of all older adults in Mexico. It is general-purpose
(YouTube, web search, Google Classroom, Gmail, WhatsApp Web) and handles government procedures (SAT, IMSS, CURP lookup,
citas). Every step is explained in plain Spanish.

**Direction:** drive the user's *real* Chromium through a Chrome MV3 extension with a side panel, keeping the Python
brain, and expose it over MCP. The roadmap is `docs/PLAN.md`.

## Start here (agents)
1. Read this file, then `docs/PLAN.md` (status + roadmap), then the **current phase file** in `docs/tasks/`. Also read
   the specs it cites: `docs/PROTOCOL.md` for messages and `docs/SAFETY.md` for safety rules, which are normative.
2. Branch: work on the branch your session designates. It must contain commit `d61fb9b` (P1 scaffold) and these docs.
   If it doesn't, run `git fetch origin claude/great-tesla-n785k5`, then `git merge origin/claude/great-tesla-n785k5`
   before anything else. Never push to `main`.
3. Execute steps **in order**. A step is done only when its *Verify* passes. In the same commit, tick the step's
   checkbox in `docs/tasks/P<n>.md`.
4. Commit after each step with the message `P<n>.<k>: <imperative summary>`, add your session's attribution lines,
   and push with `git push -u origin <branch>`.
5. When a phase is complete, update the Status table below and in `docs/PLAN.md`, plus the Layout and Commands sections.
6. If the plan conflicts with reality (an API changed, or a test is impossible as written), make the smallest change that
   keeps the spec's intent. Update the affected spec or task doc in the same commit and add a line to the Decisions log.
   **Never weaken `docs/SAFETY.md`.**
7. **Stop and ask the user** when a step needs:
   - real personal data, real accounts or logins, CAPTCHAs or payments (all live verification is the user's job);
   - weakening or bypassing a safety rule;
   - a dependency the plan doesn't list.
   Also stop when a test still fails after 3 focused attempts; report what you tried.
8. Never:
   - open a PR unless asked;
   - commit `.env`, `node_modules/`, `extension/dist/`, `.venv/` or real PII;
   - edit `babas/drivers/page_script.js` by hand (it is generated by `npm run build`);
   - add any flag or parameter that skips a confirmation.

## Environment and commands
Cloud container (Claude Code on the web):
- Python 3.13 and Node 22. Chromium build 1194 is preinstalled at `/opt/pw-browsers` (`PLAYWRIGHT_BROWSERS_PATH`).
- Pin `playwright==1.56.0` and **never run `playwright install` there**. CI does install its own browser.
- PyPI downloads are slow (~100 KB/s), so run `pip` in the background.
```bash
python3 -m venv .venv && . .venv/bin/activate && pip install -U pip
pip install "playwright==1.56.0" && pip install -e '.[dev]'
(cd extension && npm ci && npm run typecheck && npm test && npm run build)   # build also regenerates babas/drivers/page_script.js
pytest -q                          # unit + e2e (~2 min); e2e needs extension/dist (skips otherwise), BABAS_EXT_DIST overrides it
python -m babas                    # console agent (needs OPENAI_API_KEY in .env)
python -m babas serve              # side panel tasks: load extension/dist, click the BABAS icon (add --mcp-http for MCP at http://127.0.0.1:8766/mcp)
python -m babas serve --repl       # developer console through the extension (no AI)
python -m babas pair [--reset]     # show / remove the pairing file (~/.babas/pairing.json)
python -m babas mcp                # MCP over stdio (needs the extra: pip install -e '.[mcp]')
```
To load the extension by hand: `chrome://extensions` → Developer mode → Load unpacked → `extension/dist` (always after a
full `npm run build`). Then click the BABAS icon to open the side panel. Tests load it with Playwright:
`launch_persistent_context(dir, channel="chromium", headless=True, args=["--disable-extensions-except=DIST", "--load-extension=DIST"])`.
Set `chrome.storage.local.bridgePort` from the service worker to point it at a test server.

## Conventions
- Python ≥3.10 (the container runs 3.13): no `asyncio.TaskGroup`, `asyncio.timeout`, `typing.Self` or `except*`.
  Type hints on signatures, English identifiers, Pydantic v2.
- Async everywhere below the CLI. Blocking calls (`input`, voice GUI) go through `asyncio.to_thread`. Stop means
  cancelling the run task, so never swallow `asyncio.CancelledError`.
- Almost no comments (stripped on purpose in c99721f); add one only for a non-obvious *why*.
- Errors crossing layers are `DriverError(code, message, data)` with codes from `docs/PROTOCOL.md` §2. New code uses
  `except Exception`, never bare `except:`.
- Logging: `logging.getLogger("babas.<module>")` to stderr through the redacting filter. Only `cli.py` and `devrepl.py`
  print, because they are consoles.
- Anything from the LLM, the bridge or the page is parsed (Pydantic in Python, guards in TS) and never trusted.
- TypeScript: strict mode, no framework, no runtime dependencies. Pinned devDependencies only: vite 7.3.6,
  vitest 3.2.7, typescript 5.9.3, happy-dom 20.14.5, @types/chrome 0.1.43.
- User-facing text (side panel, `ui.log`, confirmation and handoff texts, final answers) is es-MX, plain language,
  "usted", no jargon. Developer-facing text (CLI, logs, errors, code) is English. Panel strings live in `_locales`.
- Configuration comes from `Settings.from_env()` (built once per entry point and passed down), never from scattered
  `os.getenv` reads; `docs/providers.md` lists every variable.
- Secrets only in `.env`. Never log or persist passwords; PII is masked by `redact()` everywhere except the
  confirmation card.
- Tests: pytest (`asyncio_mode=auto`) and vitest; browser tests carry the `e2e` marker. Every safety rule has a test (`docs/SAFETY.md` §7).

## Architecture (target; details in `docs/PLAN.md` and `docs/PROTOCOL.md`)
- Python: `Agent` (observe → plan → act, recovery) → `SafeDriver` gate (`SafetyPolicy` + `UserChannel`) → `BrowserDriver`.
  The driver is either `PlaywrightDriver` (native input, `page_script.js` for snapshots) or `ExtensionDriver`, which
  talks to the bridge (`BridgeServer`, `ws://127.0.0.1:8765`).
- Extension: SW (bridge client, tab scope, allowlist, approvals, halt, panel port) → content script (page module) and
  the side panel (chat, step log, Stop, confirmation, ask and allow cards).
- LLM: `LLMClient.complete_json(system, user, schema)`, implemented for any OpenAI-compatible endpoint
  (`base_url` + `api_key` + `model`), with Anthropic optional.
- MCP (mcp 2.x `MCPServer`): `run_task`, `get_page_state`, `act`, all through the same gate.

## Safety (summary; `docs/SAFETY.md` is normative)
- Confirm before:
  - submitting a non-search form;
  - consequential clicks (send, turn in, pay, buy, delete, post, sign, book, confirm, transfer, request, register);
  - payments;
  - typing PII (CURP, RFC, NSS, email, phone, card), whether by field or by value.
- Never type passwords or solve CAPTCHAs; hand them to the user (`ask_user` with kind `handoff`).
- Allowlist with curated defaults; any other site needs the user's "Permitir". Limits: `max_steps` 30, `max_retries` 2.
- Stop always works: the SW halts and Python cancels. Fail closed. "No" ends the run cleanly. Page text is untrusted.

## Pitfalls (learned in this repo)
- `.gitignore` ignores `*.png` (except `extension/public/icons/` and `docs/media/`), `lib/`, `build/` and `dist/`.
  Never name a source directory `lib`.
- Change anything in `extension/src/page` or `src/shared` → run `npm run build` → commit the regenerated
  `babas/drivers/page_script.js`. CI fails if it is stale.
- Branded Chrome ≥137 ignores `--load-extension`, so automated tests use Playwright's Chromium with `channel="chromium"`.
- websockets ≥15 honors `HTTPS_PROXY`: test clients must pass `proxy=None` and an explicit `origin=`.
- MV3 service workers sleep after 30 s idle. The SW pings every 20 s and an alarm reconnects every 30 s. Keep state in
  `chrome.storage.session`/`local`, never only in module variables that must survive.
- The content script runs in an isolated world. `page_script.js` in the Playwright path runs in the main world, where
  the page could tamper with it, so on that path only Python enforces safety.
- Element indices only hold for their `snapshot_id`. A stale one gives `STALE_SNAPSHOT`: observe again, don't guess.
- `chrome.sidePanel.open()` needs a user gesture. Pending confirmations wait, with the badge showing "!", until the user opens the panel.
- Synthetic DOM events have `isTrusted=false`, and some sites ignore them. Record those sites in `docs/manual-tests.md`.
- MCP SDK 2.x: `MCPServer` (not `FastMCP`), with snake_case result fields. openai 3.x uses `httpx2`, so test against the
  local fake HTTP server, not httpx mocks.
- In MCP stdio mode, stdout is the protocol channel: never print.
- Ollama silently truncates long prompts unless started with `OLLAMA_CONTEXT_LENGTH` ≥16k.
- The legacy CLI treats any input containing "hack" (including Spanish "hackear") as the hacker easter egg. It stays CLI-only.
- Never `asyncio.to_thread(input)`: a worker blocked in `input()` hangs the process after Ctrl+C until Enter is pressed.
  Use a daemon-thread reader (`_ainput` in `cli.py` and `devrepl.py`). Under a real tty a daemon thread blocked in
  `input()` can also deadlock the interpreter's exit-time flush, so `cli.main()` ends with `os._exit(130)` in that case.
- `grep sync_api` also matches `async_api`. Check with `grep -rn "playwright.sync_api\|sync_playwright" babas/`.
- Tests set `chrome.storage.local.bridgePort` through the service worker, and the worker handle can come back before
  `chrome.*` is bound inside it: retry briefly (`_set_bridge_port` in `tests/conftest.py`).
- A click on a covered element is `OBSCURED` through the extension, but `TIMEOUT` after 5 s through Playwright's native actionability checks.
- The manifest declares `side_panel`: Chromium refuses to load the extension if `dist/` lacks `sidepanel.html`, so always
  use the full `npm run build` (its last step builds the panel). Parallel work uses private copies of the extension, never
  the repo's `dist` (a build in the repo clobbers `dist` and `page_script.js`).
- `chrome.i18n` follows the browser UI language, not the Playwright locale: tests launch Chromium with `LANGUAGE=es_MX:es`
  (`tests/conftest.py`). `default_locale: es` is only a fallback, so a Chrome with an English UI shows the English panel.
- `asyncio.wait_for` can swallow a cancellation that arrives together with its result on Python < 3.12: anything on the
  Stop path must use `asyncio.wait` (`BridgeServer.request` does; `Session` also re-cancels).
- Approvals are bound to tab + host + action digest and consumed right before the page action; `allowedSites` defaults
  apply while the storage key is unset (an install-time write raced with test setup).
- The agent redacts `ask_user` answers that look like PII in its history, so the LLM cannot type them (P4.2 needs a
  placeholder mechanism). Tabs opened by pages (`target=_blank`) are outside the BABAS tab set.
- MCP stdio: stdout is the protocol channel, so nothing on the `mcp` path may print (logs go to stderr). `MCPServer(...)`
  installs a root log handler that duplicates every log line; `build_mcp_server` removes it. The HTTP endpoint is
  loopback-only with Host/Origin checks (it has no authentication): never bind it elsewhere.
- Provider quirks: some OpenAI-compatible servers reject `json_schema`/`json_object` (auto mode falls back on HTTP 400/422
  only), wrap JSON in fences or `<think>` blocks (`extract_json` handles both). `make_llm` never raises for a missing key:
  the first call raises `LLMConfigError`, which `Session` and the MCP runtime report per task.
- CDP mode uses a separate BABAS profile because Chrome 136+ refuses to debug the default one. That is why the extension exists.

  - "No" ends the run.
  - MCP SDK 2.x API.
  - The pinned extension ID comes from a generated key whose private half was discarded (not needed for unpacked loading).
- 2026-10-11 (P1 implementation):
  - Optional voice modules load lazily (`babas/voice.py`), so importing `babas.agent`/`babas.cli` prints nothing.
  - Console input uses a daemon-thread `_ainput`; Ctrl+C at the prompt now exits (P2.12 adds SIGINT -> cancel of the run).
  - `ExtensionDriver.new_tab` rejects duplicate names (`BAD_REQUEST`); `PlaywrightDriver` keeps the legacy overwrite.
  - The CI workflow and the generated `page_script.js` freshness check ship with P1.
- 2026-10-11 (P2 implementation):
  - Extension floor is stricter than the playbook: approvals bound to tab/host/digest and consumed at the last moment,
    injective digests, allowlist exemptions only for tab.info/switch/close/new-without-url, `<=50` pending UI requests.
  - The Python gate is stricter too (single-character `press` = typing, non-http(s) URLs refused, hardened host parsing).
  - An explicit `screenshot` action writes `screenshot_*.png` to the working directory (SAFETY.md §6 clarified).
  - P2 was committed locally first (the user asked for no push, PR or CI wait), then pushed on request.
- 2026-10-12 (P3 implementation):
  - `BABAS_ALLOWED_DOMAINS` extends the default allowlist (`*` = all); the extension still enforces its own list.
  - `make_llm` is lazy about configuration errors (per-task `LLMConfigError`), so MCP servers and `serve` always start.
  - The MCP HTTP transport is loopback-only with DNS-rebinding protection and runs its own uvicorn server.
  - `act` over MCP refuses element indices before a `get_page_state`; `run_task` and `get_page_state` mask personal data.
